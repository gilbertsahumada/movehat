## Usage

```bash
movehat init [project-name] [--force]
```

Initialize a new Movehat project with the standard project structure.
Movehat does not overwrite an existing destination silently. In a terminal it
asks first; in CI and other non-interactive environments you must pass
`--force`. That flag overwrites only template-owned files and preserves other
files already in the directory.

## Examples

```bash
# Create a new project in a new directory
movehat init my-project

# Prompt for a project name
movehat init

# Explicitly refresh template files in an existing destination
movehat init my-project --force
```

## Generated Structure

```
my-project/
├── move/                     # Move smart contracts
│   ├── Move.toml
│   └── sources/
│       └── Counter.move
├── scripts/                  # Deployment scripts (TypeScript)
│   └── deploy-counter.ts
├── tests/                    # Test files (TypeScript)
│   └── Counter.test.ts
├── movehat.config.ts         # Movehat configuration
├── .env.example
├── package.json
└── tsconfig.json
```

## What It Creates

- **Counter.move** — A sample Move smart contract with increment/decrement functions and Move unit tests
- **Counter.test.ts** — TypeScript integration test file using `Harness.createLocal`
- **deploy-counter.ts** — Deployment script using `Harness.createLive` + `deployCodeObject`
- **movehat.config.ts** — Network configuration (testnet, mainnet, local)
- **package.json** — Dependencies including `movehat`
- **.env.example** — Secret-free environment variable template

The generated package requires Node.js 20 or newer and pins the installed
Movehat version instead of depending on the moving `latest` tag.
