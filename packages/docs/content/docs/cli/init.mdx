## Usage

```bash
movehat init [project-name] [--force]
```

Initialize a new Movehat project with the standard project structure.

In a terminal, omitting the project name opens a prompt. In CI or another
non-interactive shell, provide the name explicitly. If the destination already
exists, Movehat asks before replacing template-owned files; non-interactive
runs fail safely unless `--force` is present. User files that are not part of
the template are preserved.

## Examples

```bash
# Create a new project in a new directory
movehat init my-project

# Prompt for the project name in an interactive terminal
movehat init

# Explicitly refresh template files in an existing destination
movehat init my-project --force
```

## Generated Structure

```
my-project/
├── move/                     # Move smart contracts
│   ├── Move.toml
│   └── sources/
│       └── Counter.move
├── scripts/                  # Deployment scripts (TypeScript)
│   └── deploy-counter.ts
├── tests/                    # Test files (TypeScript)
│   └── Counter.test.ts
├── movehat.config.ts         # Movehat configuration
├── .env.example
├── package.json
└── tsconfig.json
```

## What It Creates

- **Counter.move** — A sample Move smart contract with increment/decrement functions and Move unit tests
- **Counter.test.ts** — TypeScript integration test file using `Harness.createLocal`
- **deploy-counter.ts** — Local-by-default deployment script; public networks use `Harness.createLive`
- **movehat.config.ts** — Network configuration with `local` as the safe default
- **package.json** — Dependencies including the exact installed `movehat` version
- **.env.example** — Environment variable template
