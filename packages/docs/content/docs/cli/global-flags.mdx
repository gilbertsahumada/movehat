These flags are available on every `movehat` command. Pass them before or after the subcommand.

## `-v`, `--verbose`

`-v` is **counted** — repeat it to raise the verbosity level. Each level is additive on top of the previous one.

```bash
movehat test --ts          # L0 quiet (default)
movehat test --ts -v       # L1 + subprocess output
movehat test --ts -vv      # L2 + decoded events per transaction
movehat test --ts -vvv     # L3 + the call tree of your own modules
movehat test --ts -vvvv    # L4 + framework frames, natives, storage, return values
```

| Level | Flag | Adds |
|---|---|---|
| 0 | _(none)_ | System logs only — the default quiet console. |
| 1 | `-v` | Subprocess output from `movement node run-localnet` and `aptos move build / publish`, printed with a muted gray `›` prefix. |
| 2 | `-vv` | A decoded list of the events each `contract.call(...)` emitted. |
| 3 | `-vvv` | The call tree of **your** modules (framework `0x1::*` frames filtered out) on movelite; a flat write-set summary on the Movement node. |
| 4 | `-vvvv` | Full detail: framework frames, natives, storage, and return values on movelite; each state change's full decoded data on the Movement node. |

Levels 2–4 render execution traces. The full **call tree** is a **[movelite](/docs/guides/movelite)-only** capability — it requires the trace endpoint the lightweight local runtime exposes. On the full Movement node (and forks / `createLive`) the same flags render a **degraded flat trace** instead — the transaction's events, state changes, and gas, which the node's response already carries. See [Transaction traces](/docs/guides/traces) for both output formats.

When to reach for level 1 (`-v`):

- The local node fails to start and the spinner times out — `-v` reveals what `movement` is saying.
- `aptos move build` is slow on a fresh clone — `-v` shows the git-dependency download progress.
- Investigating a publish failure where the error message is generic — `-v` shows the full CLI stdout/stderr.

**Critical signals (panic, fatal, address already in use, EADDRINUSE) always surface regardless of verbosity.** You will never miss a real failure because the verbosity flag was off.

## `--network <name>`

Override the network for this invocation. Accepts `testnet`, `mainnet`, `local`, or any custom network name declared in `movehat.config.ts`.

```bash
movehat run scripts/deploy-counter.ts --network testnet
movehat fork create --network mainnet
```

If you don't pass `--network`, Movehat resolves the network in this order:
explicit API argument, `--network`/`MH_CLI_NETWORK`, legacy
`MOVEHAT_NETWORK`, `MH_DEFAULT_NETWORK`, then `defaultNetwork` in
`movehat.config.ts`. Contradictory explicit API and CLI selections fail before
an RPC request is made.

## `--redeploy`

Force redeployment of modules that already have a deployment record on disk.

```bash
movehat test --ts --redeploy   # ignore deployments/local/*.json, redeploy from scratch
```

Useful when your Move source changed but the local node's deployment cache still points at the old bytecode.

## Environment variables

| Variable | Equivalent flag | Purpose |
|---|---|---|
| `MOVEHAT_VERBOSE=1` | `-v` / `--verbose` | Surface subprocess output (level 1) |
| `MOVEHAT_VERBOSITY=<0-4>` | `-v` … `-vvvv` | Set the exact verbosity level, including the trace levels (2–4) |
| `MH_CLI_NETWORK=<name>` | `--network <name>` | Network selected by the CLI for the current process |
| `MOVEHAT_NETWORK=<name>` | legacy alias | Backward-compatible network default |
| `MH_DEFAULT_NETWORK=<name>` | — | Default used before `defaultNetwork` in config |
| `NO_COLOR=1` | — | Disable all ANSI colors and spinners |

`MOVEHAT_VERBOSE=1` remains the level-1 shorthand. `MOVEHAT_VERBOSITY` sets the precise level and takes precedence — useful in scripts or CI that want trace output without passing repeated flags.

`NO_COLOR=1` and non-TTY output (pipes, CI) auto-degrade gracefully — spinners disable, no carriage-return rewrites, output stays line-based and grep-friendly.
